AI Disclosure

Last updated 23 October 2026

I built Plainscript with substantial help from an AI coding assistant (Claude), and I want to be specific about what that means instead of vague about it. Vagueness is what reads as hiding something — specifics are what make this credible.

The short version

  • An AI coding assistant wrote most of the application's code, working from my direction. I reviewed it, tested it, and can explain how it works.
  • Every product and safety decision is mine: what the app refuses to do, how it handles not finding an interaction, and the rule that it never invents a medical fact.
  • I personally wrote and verified specific pieces myself — listed below, by name, not vaguely. The commit history backs every item.
  • Inside the app, an AI model is used in exactly one optional place, and it is locked so it can only rephrase text already pulled from an FDA label — it cannot add a new medical claim.

What I designed and decided

The rules Plainscript follows are mine, not the AI's. It never diagnoses — a full symptom-checker feature was proposed during development and I turned it down, because a tool that guesses what's wrong with you is exactly what I didn't want to build. It never calculates or recommends a dose. It never tells anyone to start, stop, or change a medication. And it never shows a green "safe" — only that nothing was found, which is a different and more honest claim. Those constraints, and the decision to build a curated, source-cited interaction list instead of pretending a free authoritative API still exists, are the core of the project, and they came from me.

What I personally wrote or verified

Specifically, not vaguely:

  • The homepage's "problem" section — the story about my cousin, in my own words, not AI-written.
  • Roughly 50 medical glossary definitions, each looked up and verified against MedlinePlus (NIH) before I added it.
  • Several entries in the curated drug-interaction list — each one I personally read on the drug's real FDA label (dailymed.nlm.nih.gov) before writing the plain-English explanation.
  • A number of smaller interface changes end-to-end: larger tap targets for accessibility, a cleanup pass on inconsistent font sizes, removing dead code, a running drug-counter on the interaction checker, a browser-tab-title feature, a "remember your last tab" feature, and the rule-count and last-reviewed-date lines on the Check tab.

I worked through each of these using a step-by-step guide written for me (not a finished answer handed to me) — reading real code, finding the right spot with a search, and writing the actual line myself. Where I used reference material for a specific change, I'm saying so here rather than letting the distinction blur.

What the AI wrote

The large majority of the codebase — the interaction-checking engine, the openFDA/RxNorm integration, the database and account system (with its row-level security), the 13-language translation system, the PWA/offline support, voice input, barcode scanning, and most of the interface — was written by Claude, directed by me, and reviewed by me. I'm not claiming to have hand-typed a 15,000-line application; a high school student building that alone, this fast, would be an unreasonable claim and I'm not making it.

The one place AI touches what a user actually sees

Plainscript has an optional "plain-English mode" that rewrites text already retrieved from an FDA label into simpler words. That is the only thing it is allowed to do — the prompt that controls it is locked server-side in a Cloudflare Worker, not editable from the browser, and it is instructed to rephrase only, never to add a claim that isn't already in the source text. Every claim in the app, AI-rephrased or not, still shows which FDA or NIH source it came from.

How to check any of this

I'd rather you verify this than take my word for it:

  • The full commit history is public. Most commits that include AI-written code carry a visible co-author marker; the more recent ones I committed and pushed myself.
  • The interaction-checking engine has 104 automated tests in the repository, which I can walk through.
  • The repository also contains the actual working guide I used — task by task, with what I did and didn't need help with — if you'd like to see the process itself, not just the result.

What I learned doing this

Honestly, the thing that stuck with me most: a missing answer and a safe answer can look exactly the same if you're not careful — my app almost showed that for Tylenol and Vicodin together, because the FDA doesn't even have a label for Vicodin anymore. Catching that bug taught me more about what "I don't know" is supposed to mean than anything else in this whole project.
